# 普通部署复制流程精简

记录时间：2026-10-23 08:27 北京时间（UTC+08:00）。用户要求移除来源缓存、重复检查和逐文件重写日志；本记录不是新增产品方案。

## 核查依据

- Open Mod Manager：iquercorb/OpenModMan，固定提交 `298759aae96e3755c25bc140629fc558fda93536`，GPL-3.0，仓库未归档，查询时最近推送为 2026-06-13。`src/OmModPack.cpp` 的 `applySource` 逐项直接调用 `Om_fileCopy`；`src/OmUtil/OmUtilFs.cpp` 的同名函数调用 Windows `CopyFileW`。`makeBackup` 先处理原目标，完成备份条目后保存 `ModBack.xml`，没有每复制一个文件重写全部清单。复制错误或取消返回失败，`restoreData` 按备份清单恢复旧文件和移除已安装条目。该核查证明其正常复制和备份/撤销路径；不据此宣称其所有断电边界已验证。
- Vortex：Nexus-Mods/Vortex，GPL-3.0，查询时最近推送为 2026-10-22。部署模块采用暂存目录及链接方案；本项目要求来源只读并支持不同卷，因此未采用其硬链接部署核心。此候选仅核查架构与入口，不宣称完成全部失败路径审计。
- HedgeModManager：thesupersonic16/HedgeModManager，MIT，查询时最近推送为 2026-07-20。本轮仅核查仓库元数据和源码树，未将其作为部署核心采用依据。

## 实际采用

| 能力 | 分类与入口 | 适配成本和验证 |
| --- | --- | --- |
| 普通来源文件复制 | 直接引用 .NET 10 `System.IO.File.Copy`；OpenModMan 仅作参考，未复制其 C++ 源码 | 无新增依赖；GitHub 与同一 API 的直接复制基准比较 |
| 配置及部署清单 | 保留现有 RHI 协调模块和 AtomicJson | 每库开始时写一次完整待执行清单，进度只留内存，提交后写一次最终结果；测试复制期间日志不变化 |
| 原件及修改保护副本 | 保留现有 BlobStore/Protection 实现 | 仅捕获需要保留的目标内容，不缓存普通来源；沿用完整版本保护规则 |
| 替换失败恢复 | 有限适配现有 FileReplacement；属于项目实现，不声称复用了成熟业务引擎 | 来源直接复制到游戏卷临时文件，现有目标临时改名，提交后清理；进程中断在 GitHub 验证 |

新操作使用 FileProtocol 2；旧日志协议继续走原恢复处理。待执行日志一次记录全部文件，重启恢复检查已完成和未开始的条目。正常执行不再对 EXE 加锁或哈希、不再重新构建完整预检、不再逐文件扫描游戏进程/工作区或回读校验复制结果。预检保留一次来源/目标内容识别，执行前使用长度与修改时间确认预检对象，目录隔离和同名覆盖规则保留。

这是日常本地文件复制模型，不承诺检测外部程序在预检后故意保持长度与时间戳不变的内容修改。文件复制系统错误仍会失败并走已有恢复；真实机器速度需要用户验收。
